03 / Learning notes

Panduan Belajar ProcessLab

Modul pendidikan yang menjelaskan konsep siklus hidup proses, PCB, dan context switching dengan cara yang mudah dipahami.

01

Pengenalan ProcessLab

▼

Apa itu ProcessLab? ProcessLab adalah simulator pembelajaran interaktif yang membantu Anda memahami bagaimana Sistem Operasi mengelola proses, mulai dari pembuatan hingga pengakhiran.

Mengapa simulator ini dibuat? Untuk menjelaskan konsep Sistem Operasi tanpa harus menghafal kode. Semua tindakan diantarmuka mencerminkan perubahan status proses yang nyata dalam simulasi.

Perbedaan simulator dan Sistem Operasi nyata: ProcessLab bukan pengelola proses Windows asli. Nilai PC, register AX, dan tick adalah ilustrasi edukasi, bukan data CPU fisik.

02

Lima Status Proses

▼
NEW

Proses Dibuat

Proses baru dibuat oleh program atau pengguna.

Masuk ke READY setelah ditambahkan ke antrean.

READY

Siap CPU

Proses menunggu giliran untuk menggunakan CPU.

Masuk ke RUNNING saat dijadwalkan CPU.

RUNNING

Dieksekusi

Proses sedang memakai CPU untuk menjalankan instruksi.

Kembali ke READY melalui Context Switch.

WAITING

Menunggu I/O

Proses menunggu input/output atau kejadian tertentu.

Kembali ke READY setelah I/O selesai.

TERMINATED

Selesai

Proses telah menyelesaikan eksekusi.

Tidak dapat dijalankan kembali.

READY vs WAITING: READY artinya menunggu CPU tersedia. WAITING artinya menunggu I/O selesai sebelum kembali layak dijalankan.
03

Process Control Block (PCB)

▼

PCB menyimpan semua informasi yang diperlukan Sistem Operasi untuk mengelola satu proses.

PID 1001 Identifikasi unik proses
Nama Editor Dokumen Nama proses yang ditampilkan
Status RUNNING Status siklus hidup saat ini
Program Counter PC = 8 Instruksi selanjutnya yang akan dieksekusi
Register AX AX = 24 Nilai register ilustrasi
Tick 8 Jumlah kali proses dieksekusi

Nilai di atas adalah contoh ilustrasi dari mode Demo ProcessLab, bukan data CPU fisik asli.

04

CPU Execution & Tick

▼

Satu CPU Tick mewakili satu satuan eksekusi proses. Dalam ProcessLab:

  • PC bertambah 1 setiap tick
  • AX bertambah 3 modulo 256 setiap tick
  • Tick count bertambah 1 setiap kali proses dieksekusi
  • CPU Tick total bertambah 1 setiap tick dieksekusi

Sebelum Tick

PC = 0
AX = 0

→

Setelah 1 Tick

PC = 1
AX = 3

→

Setelah 2 Tick

PC = 2

05

Context Switching

▼

Sebelum Switch

Editor Dokumen RUNNING
Browser READY
Pemutar Musik WAITING
CPU: Editor Dokumen
Context Switch: 0
→

Setelah Switch

Editor Dokumen READY
Browser RUNNING
Pemutar Musik WAITING
CPU: Browser
Context Switch: 1
Alur Context Switch
  1. CPU mengeksekusi Editor Dokumen.
  2. Browser dipilih sebagai proses READY.
  3. Tombol Context Switch ditekan.
  4. Konteks Editor (PC, AX) disimpan.
  5. Konteks Browser (PC, AX) dipulihkan.
  6. CPU melanjutkan eksekusi Browser.

Memilih proses berbeda dengan berpindah CPU. Context Switch baru terjadi saat tombol Context Switch diklik dan CPU benar-benar pindah proses.

07

Praktik Langsung

▼

Scenario A — Dari Nol

  1. Klik Reset.
  2. Klik + Buat Proses.
  3. Klik New → Ready.
  4. Klik Ready → Running.
  5. Klik Eksekusi 1 Tick.
  6. Klik Running → Waiting.
  7. Klik Waiting → Ready.
  8. Klik Ready → Running.
  9. Klik Selesaikan Proses.

Scenario B — Context Switch

  1. Klik Siapkan Demo.
  2. Pastikan Editor RUNNING, Browser READY, Musik WAITING.
  3. Pilih Browser dari daftar proses.
  4. Klik Context Switch satu kali.
  5. Amati CPU, PCB, status, dan Activity Log.
  6. Klik Unduh Hasil jika diperlukan.

08

Laporan & Troubleshooting

▼

Isi hasil_simulasi_kelompok_3.txt

  • Tanggal simulasi
  • Total proses
  • CPU Tick
  • Context Switch
  • Data PCB (PID, nama, status, PC, AX, tick)
  • Riwayat aktivitas

Pastikan ada proses yang dipilih dengan status READY dan CPU sedang kosong (tidak ada proses RUNNING).

Context Switch membutuhkan proses RUNNING dan setidaknya satu proses READY. Buat dua proses terlebih dahulu.

Belum ada proses yang dijadwalkan ke CPU. Klik Ready → Running setelah membuat proses.

Buat atau jalankan setidaknya satu proses sebelum mengklik Unduh Hasil.

Simulasi berjalan di memori browser. Halaman di-refresh akan mereset semua data.

Proses TERMINATED sudah selesai dan tidak dapat dijalankan kembali dalam simulasi ini.

09

Batasan & Pengembangan

▼
Bukan pengelola proses Windows asli. ProcessLab adalah simulator edukasi, bukan pengelola sistem nyata.
Tidak ada jadwal otomatis lengkap. Tidak mengimplementasikan FCFS atau Round Robin penuh.
Tidak menyimpan sesi secara permanen. Data hilang saat halaman di-refresh.
PCB adalah model sederhana. Nilai PC, AX, dan tick adalah ilustrasi pembelajaran.

Konsep Pengembangan Masa Depan

  • Jadwal FCFS (First-Come, First-Served)
  • Jadwal Round Robin
  • Penjelasan visual yang lebih diperluas
  • Riwayat simulasi yang tersimpan

Fitur di atas adalah konsep masa depan, bukan fitur yang sudah ada dalam ProcessLab.
